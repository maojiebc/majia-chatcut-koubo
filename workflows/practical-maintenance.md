# 实战维护

每周核对官方变化并落实有实际价值的小修，每三周用真实任务做一次较大迭代。首轮为 2026-10-13，下一轮较大迭代为 2026-11-03。较大迭代不强制破坏兼容；没有价值的变化不凑版本。Codex 定时维护留在同一聊天，未变化且无需处理时保持安静。

## 先确认真实连接

读取当前官方 `chatcut-plugin-basics`，检查已注册的 Hosted 服务并完成 OAuth。不要输出整份 MCP 配置或凭据。Codex 新注册的工具可能要新会话才能加载；同一官方服务也可以使用已授权 mcporter 做只读检查，禁止为探针另装 Desktop 或切换产品面。

完整源码提供：

```sh
npm run live:probe -- --config <private-mcporter.json>
```

该本机配置必须声明 `mcpServers.chatcut.baseUrl` 为官方 Hosted MCP 地址，`headers.x-chatcut-mcp-surface` 为 `codex`。使用 mcporter 已有 OAuth；命令不发起新授权，不读取/导出 Token，也不写配置。保留配置在公开仓之外。缺 mcporter、401、超时或无效回读分别停在连接未确认；不要把 OAuth 登录回执直接当作工具调用通过。

账号读取与核心工具合同分别报告；缺核心工具或配置了工具过滤时不会返回就绪。成功只证明当前账号项目读取和核心工具清单。输出不含项目 ID、名称、URL、字幕或媒体。工具参数或描述变化会改变合同指纹，必须重新读取对应官方说明。它不是完整会话准入、项目写入、素材就绪、画面或听感验收。

## 核对官方变化

只读拉取官方 `ChatCut-Inc/agent-plugin`，读取官网 releases/changelog；不同来源版本分别记录。运行：

```sh
npm run check:official -- --checkout <official-checkout> --json
```

报告分别检查实际 Git 提交、版本、Skill 清单、已审查文件和整个 Hosted 包的文件指纹。`reviewedFiles` 记录读过并分析的内容；`watchedFiles` 只保证之后能发现 helper、配置或说明文件变化。新增监测基线不等于全部读过，也不升级真实工具或媒体证据。官方 Git 历史重写时不要猜跨提交差异，按实际内容对照，记录证据缺口。

只有这次具体审阅并验证后才更新基线。不能为了让检查变绿而自动吸收上游。没有 `--checkout` 只检查记录格式，不证明官网或上游仍是当前状态。

## 真正做一次，再发布

先完整读取实操经验库和命中案例。使用独立测试项目或明确获授权的工作项目；用当前工具 schema 确定参数。每批写入前读当前对象，写后回读；临时探针标记在收工前删除并确认。合成画面另行检查像素，音频另行测量与人耳试听。真实结构通过不能替代其他证据；没有完成的部分写 `UNVERIFIED`。

按实操暴露的问题改代码或默认方法，留下回归测试、脱敏案例和采用/拒绝记录。先跑相关检查与仓库发布门禁，再通过 majia-ota 提交、推送及完整 SHA 回读；本机同步先预演，确认来源和内容后同步并回读。新商店、付费生成、用户视频导出和公开视频发布需要对应授权，不随项目维护扩大。

完整稳剪生产闸仍由当前版本的 live canary 报告负责。连接、标记写入或一张正确画面不能把八类口播验证自动升级为通过。
