# 外挂知识包与镜头配方

本章定义 `extensions/` 的调用边界。外挂的价值是扩大候选，不是绕过口播生产的内容真相、字幕、隐私、证据、唯一合成 owner、审批或导出门禁。

## 1. 权限顺序

发生冲突时，按以下顺序裁决：

1. `rules/policy.json`、内容真相、隐私、字幕与发布硬规则；
2. 当前项目已批准的计划、视觉任务和 ChatCut capability 证据；
3. `02-剪辑方法手册/` 中已经复验的正式方法；
4. `cuttips-kb` 的知识卡和方法候选；
5. `video-shotcraft` 的外部镜头配方候选。

后级只能收窄或补充前级，不能覆盖前级。外挂不可用时，核心流程仍须完整运行。

## 2. 两类外挂

### 2.1 `cuttips-kb`：随包知识层

数据来自 198 份公开来源索引，当前快照包含：

- 12 个类别；
- 48 张原子知识卡；
- 14 条机器规则；
- 198 条来源元数据，其中 191 条 A 级双源复核、7 条 B 级待二次复核。

它适合回答“这个语义段有哪些剪法”“何时不该用”“参数、QA 和回退是什么”，但不能证明 ChatCut 当前支持某个工具，也不能替代项目素材证据。

检索示例：

```bash
# 给 AI 返回两张字幕相关知识卡
node extensions/cuttips-kb/scripts/query.mjs \
  --text 字幕 \
  --type knowledge \
  --limit 2 \
  --json

# 查 must 级规则
node extensions/cuttips-kb/scripts/query.mjs \
  --strength must \
  --type rules \
  --json

# 同时追溯知识卡、规则和来源
node extensions/cuttips-kb/scripts/query.mjs \
  --text 证据 \
  --type all \
  --limit 8 \
  --json
```

AI 使用知识卡时至少保留：

- `id`：稳定引用；
- `whenToUse` 与 `whenNotToUse`：正反适用条件；
- `steps`：执行候选；
- `qa`：验收；
- `rollback`：失败回退；
- `sourceRefs`、`confidence`、`ruleStrength`：证据与权重。

B 级来源只能进入人工待审候选，不能独立支持破坏性剪辑、事实主张或规则晋升。

### 2.2 `video-shotcraft`：外部镜头提供器

本仓库不内嵌第三方项目、示例音频或渲染依赖，只锁定：

- 仓库和完整 commit SHA；
- Apache-2.0 许可声明；
- 经口播场景审查的卡片与 style 白名单；
- 语义信号、禁用条件、使用频率、合成 owner 和回退动作；
- 本地 checkout 的 revision、library、卡片和 style 校验器。

需要使用时，由操作者在独立目录取得清单锁定的 revision，再验证：

```bash
node extensions/video-shotcraft/scripts/inspect-provider.mjs \
  --checkout <video-shotcraft-checkout>
```

revision 不一致、library 缺失、白名单卡片消失或 style 漂移，全部 fail closed。升级 Shotcraft 不能只改 SHA：必须重新审查白名单、许可、音频来源和实际渲染。

## 3. AI 决策协议

每个语义段只允许一个主视觉任务。建议输出以下候选合同：

```json
{
  "segmentId": "<segment-id>",
  "primaryVisualTask": "解释一个真实数据变化",
  "knowledgeRefs": ["KB-..."],
  "provider": "video-shotcraft",
  "card": "chart-live-moves",
  "style": "axis-rescale-shock",
  "semanticSignals": ["真实数据变化", "增长"],
  "evidenceRefs": ["<project-evidence-id>"],
  "renderMode": "full-frame",
  "compositionOwner": "external-mg",
  "fpsContract": {
    "timelineFps": "<measured>",
    "renderFps": "<declared>",
    "timingDomain": "seconds"
  },
  "fallback": "静态真图表加简单高亮",
  "status": "pending-human-review"
}
```

其中 `knowledgeRefs` 解释“为什么这样剪”，`evidenceRefs` 证明“画面中的内容是真的”。两者不可互相代替。

候选选择流程：

1. 从剪后 transcript 和项目计划确定语义段、主张、风险词与唯一主视觉任务；
2. 查询 `cuttips-kb`，保留正反条件、步骤、QA 与回退；
3. 先尝试 ChatCut 原生、静态信息块或真实 B-roll；
4. 只有静态方案不足且语义命中时，才匹配 Shotcraft allowlist；
5. 校验禁用条件、素材真实性、版权、重复度、阅读时间与合成 owner；
6. 人工批准后渲染，输出 fps、时长、透明/满屏模式和文件 hash；
7. 导入 ChatCut 后只允许一个画面系统拥有最终像素；
8. 用结构回读、云端合成帧和实际试听验收；失败立刻执行合同中的 fallback。

## 4. 首批 Shotcraft 白名单的口播映射

| 卡片 | 适用信息任务 | 关键禁用条件 | 默认回退 |
| --- | --- | --- | --- |
| `speed-ramp-freeze / freeze-annotate` | 教学重点停住标注 | 没有真实画面或标注未经核验 | 静态截图 + 箭头 |
| `title-demote-to-label` | 章节标题降为方位标签 | 标题未经授权改写、停留过长 | 静态章节标签 |
| `chart-live-moves` | 真实数据、构成、增长 | 无可追溯数据、动画夸大关系 | 静态真图表 |
| `type-rhythm-sync / karaoke-fill-sync` | 短标语逐词跟读 | 替代正式字幕、未绑定剪后音频 | 关键词静态强调 |
| `before-after-slider-scrub` | 同对象前后对比 | 对象/尺度不一致、不能证明主张 | 并排真图 |
| `ai-stream-response` | AI 生成结果与证据汇入 | 虚构产品响应或证据 | 真实录屏/信息卡 |
| `voice-waveform-live` | 语音输入或监听状态 | 冒充真实录音证据 | 静态状态图标 |
| `paper-title-card` | 章节呼吸位 | 高频重复、切断语义连续性 | 简洁章节卡 |

明确不进入默认白名单：

- 黑帧频闪、强闪烁：存在光敏风险，也与现有无闪黑门禁冲突；
- 重霓虹、故障、粒子和动漫冲击：默认不符合知识口播的阅读优先级；
- 高能群像片尾：与自然收束、避免硬 CTA 的基线冲突；
- 未逐文件确认许可的第三方音频。

## 5. 合成与时间硬约束

- 外部 MG 是 artifact provider，不是第二个视觉决策者。
- 同一时间范围只能有一个 `compositionOwner`；不得由 ChatCut shader 和外部 MG 重复做同一套框、蒙版或位移。
- Shotcraft 示例参数只能作为配方起点。所有帧参数先换算为秒，再按当前时间线和真实导出 fps 归一化。
- 一份母资产可以通过多个 source offset 复用，但每个片段仍须保存 logical ID、source range、timeline range 和文件 hash。
- 外部片段不得偷偷带入未知音频；默认静音导入，声音另走 ChatCut 已核验路径。
- 生成 UI、图表、波形和对比图都不能冒充真实产品界面、数据或证据。
- 任何动态方案都必须有静态、原生或手工可执行的 fallback。

## 6. 更新与验证

```bash
# 验证快照 checksum、引用完整性、数量、脱敏和 Shotcraft 白名单合同
npm run validate:extensions

# 与全仓规则、测试、公开安全和版本一致性一起验证
npm run verify
```

更新百科快照时必须同步来源 commit、生成时间、数量和每个文件的 SHA-256。更新外部 provider 时必须锁定完整 SHA；不能跟随浮动 `main` 自动执行远端代码。

外挂经验若只在一个任务中成功，先写入 `03-实操迭代与踩坑/`。只有跨案例复验、有 E2/E3 证据并包含反例与回退后，才可晋升到正式方法或 `rules/`。
